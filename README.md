# بنام آکادمی — پلتفرم آموزش حسابداری

سایت آموزشی با پنل مدیریت کامل. فرانت‌اند خالص (HTML/CSS/JS) بدون فریم‌ورک و بدون مرحله بیلد.

---

## اجرای پروژه

هر سرور استاتیکی کافی است. با افزونه Live Server در VS Code:

```
پورت Live Server: 5503  (در .vscode/settings.json تنظیم شده)
صفحه شروع:       html/index.html

برای پایتون، دستور نمونهٔ زیر مستقل است و از پورت 5501 استفاده می‌کند:
```

یا با پایتون:

```bash
python3 -m http.server 5501
# سپس http://localhost:5501/html/index.html
```

> پروژه باید از طریق سرور باز شود، نه با دوبار کلیک روی فایل. مسیرهای نسبی و `fetch` با پروتکل `file://` کار نمی‌کنند.

---

## ساختار پروژه

```text
index.html               ورودی ریشه؛ برای GitHub Pages به html/index.html هدایت می‌کند
html/                    صفحات سایت و پنل مدیریت
scripts/api.js            لایهٔ درخواست‌های HTTP و قرارداد appApi؛ mock server در ریپو نیست
scripts/admin/            منطق پنل؛ فایل‌ها در یک scope سراسری بارگذاری می‌شوند، boot.js آخر
scripts/admin-content/    منطق تب مدیریت محتوای پنل
scripts/                 منطق صفحات، هدر/فوتر و داده‌های ثابت/محلی
styles/header, main,
       pages, footer/     استایل‌های مشترک و صفحه‌محور
images/                  تصاویر و نشان‌ها
files/                   محل فایل دانلودی؛ فایل‌ها به‌جز README و .gitignore در Git نیستند
docs/                    قرارداد API، تحویل بک‌اند و راهنماها
tests/                   تست‌ها و helpers؛ اجرا با npm test
```

این ریپو فرانت‌اند است و فولدر بک‌اند ندارد. مسیرها را فعلاً جابه‌جا نکنید: صفحه‌ها و تست‌ها به مسیرهای نسبی و ترتیب بارگذاری اسکریپت‌های کلاسیک وابسته‌اند. نقشهٔ جزئی‌تر: [`docs/نقشه-فایل‌ها.md`](docs/نقشه-فایل‌ها.md).

## ارتباط فرانت‌اند و بک‌اند

درخواست‌های API از `appApi` در `scripts/api.js` با `fetch` ارسال می‌شوند. هیچ فایل `api-mock-*.js` در ریپوی فعلی وجود ندارد؛ `apiMode` هم در حال حاضر mock/real را سوییچ نمی‌کند. آدرس پایه را با تنظیم `apiBaseUrl` مشخص کنید؛ اگر خالی باشد، درخواست‌ها به همان origin می‌روند.

```js
window.APP_CONFIG = {
  apiBaseUrl: "https://api.example.com",
};
```

`appApi` مرز اصلی درخواست‌های HTTP است، اما هنوز چند وضعیت نمایشی/محلی (از جمله سبد خرید، نشست توسعه، محتوای ثابت و تنظیمات منوی هدر) مستقیماً از `localStorage` یا `sessionStorage` خوانده می‌شوند. این‌ها به‌صورت خودکار با اتصال `api.js` به دیتابیس منتقل نمی‌شوند؛ فهرست و نکات مهاجرت را در [`docs/تحویل-به-بک‌اند.md`](docs/تحویل-به-بک‌اند.md) ببینید.

قرارداد endpointها: [`docs/API_CONTRACT.md`](docs/API_CONTRACT.md)

## اتصال پنل ادمین به سایت

| تغییر در پنل                   | اثر روی سایت                          |
| ------------------------------ | ------------------------------------- |
| افزودن محتوا (ویو محتوای سایت) | در صفحه اصلی و لیست مطالب ظاهر می‌شود |
| افزودن محصول                   | قفل دانلود و قیمت در صفحه تک‌مطلب     |
| تغییر ایمیل/تلفن پشتیبانی      | فوتر تمام صفحات                       |
| فعال کردن حالت تعمیر           | کل سایت عمومی قفل می‌شود              |
| پاسخ به پیام                   | در ترد گفتگوی کاربر ثبت می‌شود        |

و در جهت معکوس:

| اقدام کاربر در سایت | نمایش در پنل                           |
| ------------------- | -------------------------------------- |
| ارسال فرم تماس      | صندوق پیام‌ها                          |
| ثبت‌نام             | لیست کاربران (با برچسب `source: site`) |
| تکمیل خرید          | لیست سفارشات                           |

آدرس: `html/admin.html`

## وضعیت فعلی: بدون رمز

گیت احراز هویت با یک سوییچ در `scripts/admin/auth.js` خاموش است:

```js
const ADMIN_AUTH_ENABLED = false;
```

یعنی `html/admin.html` مستقیم باز می‌شود و رمزی نمی‌خواهد. این برای مرحله توسعه است.

⚠️ **پیش از انتشار سایت، این مقدار را `true` کنید** — یا بهتر، محافظت سمت سرور را پیاده کنید (توضیح در `docs/API_CONTRACT.md`).

## مسیر درست ورود ادمین

ادمین مثل هر کاربر دیگری از `sign-up.html` وارد می‌شود. تفاوت در چیزی است که بعد از ورود در هدر می‌بیند.

۱. کاربر با ایمیل و رمز وارد می‌شود
۲. سرور (فعلاً mock) نقش او را در session برمی‌گرداند
۳. `app-shell.js` هدر را بازسازی می‌کند

| وضعیت                           | هدر                             |
| ------------------------------- | ------------------------------- |
| پیش‌فرض (مرورگر تازه، بدون سشن) | **پنل مدیریت** · خروج           |
| خروج داده‌شده (در همین نشست)    | ورود / عضویت                    |
| کاربر عادی                      | **پروفایل** · خروج              |
| حساب staff                      | **پنل مدیریت** · خروج           |

> **حالت پیش‌فرض نمایشی:** سایت طوری تحویل داده می‌شود که گویی «مدیر سایت» وارد شده — بازدیدکنندهٔ تازه در هدر «پنل مدیریت · خروج» می‌بیند، نه «ورود / عضویت». کلید «خروج» در همان نشست مرورگر واقعاً خروج می‌کند و تا بستن همان تب همان‌‌طور می‌ماند؛ با باز کردن تب/مرورگر تازه، سشن پیش‌فرض دوباره ساخته می‌شود. فعال بودن حالت تعمیر مانع از ساخت سشن پیش‌فرض می‌شود تا بازدیدکننده همچنان صفحهٔ قفل را ببیند.
> پیش از انتشار با بک‌اند واقعی، `seedDefaultSession()` را از `scripts/app-shell.js` حذف کنید (توضیح داخل فایل).

نقش‌هایی که staff محسوب می‌شوند: `مدیر سایت` · `مدیر سیستم` · `ادمین`

ادمین‌ها لینک «پروفایل» نمی‌بینند چون حساب خود را داخل پنل مدیریت ویرایش می‌کنند. دو در به یک مقصد، فقط سردرگمی می‌سازد.

وقتی ادمین داخل پنل است، لینک هدر به «بازگشت به سایت» تغییر می‌کند تا به صفحه فعلی اشاره نکند. خروج از حساب هم از دکمه سایدبار پنل انجام می‌شود.

منوی موبایل هم همین قواعد را دنبال می‌کند.

### ساختن یک حساب ادمین برای تست

در کنسول مرورگر (F12):

```js
// اگر هنوز حسابی ندارید
await appApi.auth.register({
  name: "مدیر سایت",
  email: "admin@test.com",
  password: "123456",
});

// ارتقا به مدیر
await appApi.auth.promote({ email: "admin@test.com", role: "مدیر سایت" });

location.reload();
```

حالا لینک «پنل مدیریت» در هدر ظاهر می‌شود.

> `appApi.auth.promote` یک کمکی موقت برای توسعه است. با آمدن بک‌اند حذف می‌شود و جایش را `PATCH /admin/users/:id/role` با بررسی دسترسی می‌گیرد.

## وقتی گیت را روشن کنید

با `ADMIN_AUTH_ENABLED = true`، اولین باز کردن پنل از شما می‌خواهد یک رمز انتخاب کنید (حداقل ۶ کاراکتر، با تکرار). دفعات بعد همان رمز را می‌خواهد.

**فراموشی رمز:**

```js
localStorage.removeItem("benamacademyAdminPassword");
localStorage.removeItem("benamacademySession");
location.reload();
```

**خروج از حساب:**

```js
localStorage.removeItem("benamacademySession");
location.reload();
```

**دور زدن موقت:** `html/admin.html?dev=1`

## تغییر نقش هنگام توسعه

در حالت لوکال که `ADMIN_AUTH_ENABLED = false` است، شما به‌صورت پیش‌فرض **مدیر سایت** با دسترسی کامل هستید.

برای بررسی اینکه یک «ادمین» چه می‌بیند، در کنسول مرورگر:

```js
adminDev.whoami(); // نقش فعلی را نشان می‌دهد
adminDev.asAdmin(); // تبدیل به ادمین (دسترسی محدود)
adminDev.asManager(); // بازگشت به مدیر سایت
adminDev.reset(); // پاک کردن سشن
```

هر کدام صفحه را رفرش می‌کنند.

> این ابزار فقط در حالت توسعه معنا دارد و باید پیش از انتشار حذف شود. در سورس با `BACKEND NOTE` علامت خورده است.

برای توسعه محلی می‌توانید گیت را با `?dev=1` دور بزنید:

```
html/admin.html?dev=1
```

> این گیت سمت کلاینت است و امنیت واقعی محسوب نمی‌شود. محافظت اصلی باید سمت سرور اعمال شود — توضیح در `docs/API_CONTRACT.md`.

## تست

```bash
npm test
```

وابستگی تست `jsdom` در `package.json` تعریف شده است. تست‌ها رفتار فرانت‌اند را بررسی می‌کنند و جایگزین تست اتصال به backend واقعی نیستند.

برای راهنمای آپلود فایل و ویدیو، به `docs/راهنمای-افزودن-محصول.md` مراجعه کنید.

### نکته درباره SRI

هر صفحه یک `integrity` روی لینک Font Awesome دارد. اگر نسخه کتابخانه را عوض
کردید، **حتماً** هش را هم به‌روز کنید وگرنه مرورگر فایل را بلاک می‌کند و هیچ
آیکونی نمایش داده نمی‌شود:

```bash
curl -s https://cdnjs.cloudflare.com/ajax/libs/font-awesome/<نسخه>/css/all.min.css \
  | openssl dgst -sha384 -binary | openssl base64 -A
```

`tests/admin-ui.test.js` این تطابق را برای همه صفحات بررسی می‌کند.

## قراردادهای کد

- **درخواست HTTP:** از `appApi` استفاده کنید؛ دادهٔ مرورگری فعلی را همه‌جا پشت این لایه فرض نکنید.
- **state محلی:** تعدادی قابلیت هنوز مستقیم از `localStorage`/`sessionStorage` استفاده می‌کنند؛ پیش از مهاجرت، `docs/تحویل-به-بک‌اند.md` را ببینید.
- **متغیرهای CSS:** از `styles/main/variables.css` استفاده کنید.
- **زبان:** صفحات فارسی `lang="fa" dir="rtl"` دارند.
- **نقاط اتصال بک‌اند:** با کامنت `BACKEND NOTE` علامت‌گذاری شده‌اند.

```bash
grep -rn "BACKEND NOTE" scripts/
```
