# نقشهٔ پروژه — مسیر هر بخش کجاست؟

این ریپو یک فرانت‌اند ایستا با HTML/CSS/JavaScript کلاسیک است؛ فولدر یا سرویس بک‌اند در آن وجود ندارد. مسیر فایل‌ها را فعلاً جابه‌جا نکنید: HTML و تست‌ها به مسیرهای نسبی و ترتیب بارگذاری اسکریپت‌ها وابسته‌اند.

## ساختار فولدرها

```text
index.html                  ورودی ریشه؛ به html/index.html هدایت می‌کند
html/                       صفحات عمومی و admin.html
scripts/api.js              تنها adapter درخواست‌های HTTP و فهرست appApi
scripts/admin/              منطق پنل مدیریت
scripts/admin-content/      منطق تب مدیریت محتوای سایت
scripts/                    منطق صفحات، پوستهٔ مشترک، ویجت‌ها و داده‌های فرانت
styles/header/               استایل‌های هدر
styles/main/                 استایل‌های صفحهٔ اصلی و ویجت‌های مشترک
styles/pages/                استایل صفحه‌ها و تب‌های پنل
styles/footer/               استایل فوتر
images/                      تصاویر و نشان‌ها
files/                       محل فایل‌های دانلودی؛ محتوا به‌جز راهنما در Git نیست
docs/                        قرارداد API و راهنماهای تیم
tests/                       تست‌ها و helpers
```

## نقطهٔ شروع بک‌اندکار

- API و request wrapper: `scripts/api.js`
- قرارداد مسیرها، بدنه‌ها و پاسخ‌ها: `docs/API_CONTRACT.md`
- ملاحظات انتقال و داده‌های محلی: `docs/تحویل-به-بک‌اند.md`
- روش اجرا و تست: `README.md`

`appApi` درخواست‌ها را با `fetch` می‌فرستد. در ریپوی فعلی هیچ `api-mock-*.js` یا سرور mock وجود ندارد؛ مقدار `apiMode` نیز مسیر mock/real را عوض نمی‌کند. `apiBaseUrl` را در `window.APP_CONFIG` تنظیم کنید؛ اگر خالی باشد، درخواست به همان origin می‌رود.

```js
window.APP_CONFIG = { apiBaseUrl: "https://api.example.com" };
```

`appApi` مرز اصلی درخواست‌های HTTP است، نه همهٔ state پروژه: چند بخش هنوز برای دادهٔ محلی/نمایشی مستقیماً از `localStorage` یا `sessionStorage` استفاده می‌کنند. از جمله:

- سبد خرید و موقت‌های فرایند خرید: `scripts/checkout.js`, `scripts/gateway.js`, `scripts/recipt.js`, `scripts/user-profile.js`
- ترتیب/محتوای محلی، سکشن صفحهٔ اصلی و تنظیمات منوی هدر: `scripts/item-store.js`, `scripts/home-sections.js`, `scripts/data.js`, `scripts/header-custom-menu.js`, `scripts/header-labels.js`
- state اولیه و داده‌های توسعهٔ پنل: `scripts/admin/state.js`, `scripts/admin/boot.js`
- نشست نمایشی و تنظیمات محلی پوسته: `scripts/app-shell.js`, `scripts/admin/auth.js`

این موارد با تنظیم `apiBaseUrl` به‌طور خودکار به بک‌اند مهاجرت نمی‌کنند. موارد خرید، مجوز دانلود، نقش‌ها و تنظیمات حساس باید مرجع نهایی سمت سرور داشته باشند.

## ترتیب بارگذاری اسکریپت پنل

اسکریپت‌ها در `html/admin.html` به‌صورت classic script و در scope سراسری بارگذاری می‌شوند. ترتیب فعلی را حفظ کنید؛ `scripts/admin/boot.js` و `scripts/admin-content/content-table.js` به‌علت اجرای راه‌اندازی باید در انتهای گروه مربوطه بمانند. تست `tests/file-split.test.js` بخشی از این قرارداد را بررسی می‌کند.

## هشدارهای انتشار (کد مخرب نیستند، اما حالت توسعه/دمو امن انتشار عمومی نیست)

- `scripts/admin/auth.js`: `ADMIN_AUTH_ENABLED` فعلاً `false` است و ابزار `window.adminDev` به پنجره اضافه می‌شود.
- `scripts/app-shell.js`: برای دموی مرورگر تازه، نشست مدیر پیش‌فرض می‌سازد.
- `files/`: فایل‌های این مسیر با URL مستقیم عمومی‌اند؛ قرار دادن فایل پولی اینجا به‌تنهایی مجوز خرید را اعمال نمی‌کند.

پیش از انتشار واقعی باید احراز هویت و نقش‌ها سمت سرور enforce شوند؛ فایل‌های پولی باید با کنترل دسترسی/لینک امضاشده تحویل داده شوند. راهنمای دقیق‌تر در `docs/API_CONTRACT.md` است.
