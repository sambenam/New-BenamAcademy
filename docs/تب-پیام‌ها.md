# تب پیام‌ها

ویجت دستیار ابتدا به endpoint دستیار وصل می‌شود؛ پرسش‌های ارجاع‌شده و فرم تماس وارد صندوق پیام‌ها می‌شوند و پاسخ ادمین به پروفایل همان کاربر برمی‌گردد.

```
ویجت دستیار → /assistant/chat → پاسخ agent
                         └→ ارجاع انسانی → تب پیام‌ها (پنل) → پاسخ → پیام‌های من (پروفایل)
فرم تماس با ما / قوانین ───────────────────→ تب پیام‌ها (پنل)
```

---

## از کجا پیام می‌آید

| منبع           | کجاست                                         | رفتار |
| -------------- | --------------------------------------------- | ----- |
| دستیار هوشمند | ویجت گفتگو، صفحه اصلی                         | پاسخ از `/assistant/chat`؛ در ارجاع یا نبود endpoint، ثبت در صندوق پیام‌ها |
| فرم تماس با ما | `support.html` — لینک «تماس با ما» و «قوانین» | ثبت در صندوق پیام‌ها |

**نکته:** «تماس با ما» و «قوانین» در هدر هر دو به همان `support.html` می‌روند. یعنی یک فرم است، نه دو تا.

---

## باگ‌هایی که رفع شد

### ۱. پیام‌های واقعی نامرئی می‌رسیدند

API می‌نوشت `read: false` ولی پنل `msg.unread` را می‌خواند که `undefined` بود:

```js
appState.messages.filter((m) => m.unread); // همیشه صفر
```

نتیجه: هر پیام واقعی **بدون بج، بدون هایلایت و ته لیست** می‌نشست. حالا `normalizeMessage` هر دو فیلد را می‌نویسد و تابع `isUnreadMessage()` هر دو را می‌پذیرد.

### ۲. ارسال دستیار و پاسخ ثابت

پاسخ ساختگیِ `setTimeout` حذف شد. فرانت‌اند اکنون با `appApi.assistant.chat` به `/assistant/chat` درخواست می‌فرستد و با `conversationId` ادامهٔ همان گفتگو را مشخص می‌کند. اگر endpoint دستیار صریحاً موجود نباشد، پرسش از مسیر `appApi.support.sendMessage` برای انسان ثبت می‌شود؛ خطاهای دیگر به‌جای پاسخ موفقِ ساختگی، به کاربر گزارش می‌شوند. پاسخ هوش مصنوعی واقعی همچنان نیازمند پیاده‌سازی endpoint و اتصال agent در بک‌اند است.

### ۳. منبع پیام پاک می‌شد

مسیر `GET /admin/messages` روی همه پیام‌ها `source: "site"` می‌نوشت و فرقی بین ویجت و فرم تماس نمی‌ماند.

### ۴. سشن بدون ایمیل، ارسال را می‌شکست

اندپوینت `/support/messages` ایمیل را اجباری می‌داند. ویجت ایمیل را از سشن می‌خواند و اگر خالی بود، رشته تهی می‌فرستاد و پیام رد می‌شد.

سشن نمایشی `adminDev.asManager()` نام و نقش دارد، اما شناسه و ایمیل حساب ندارد. ویجت اکنون چنین سشنی را برای ارسال نمی‌پذیرد؛ باید توکن و شناسه یا ایمیل قابل‌استفاده وجود داشته باشد. اگر کاربر شناسه دارد ولی ایمیل ندارد، فقط در fallback انسانی از نشانی داخلی مبتنی بر شناسه استفاده می‌شود (`user-x9@account.local`).

فرم تماس با ما این مشکل را نداشت چون آنجا ایمیل را خود کاربر تایپ می‌کند.

### ۵. پیام خطا دروغ می‌گفت

هر خطایی — حتی اعتبارسنجی — به کاربر می‌گفت «اتصال خود را بررسی کنید». حالا علت واقعی نمایش داده می‌شود.

### ۶. ترتیب پیام‌ها تصادفی بود

آخرین پیام ارسالی اول لیست نمی‌نشست. دو دلیل داشت:

**الف) `createdAt` دور ریخته می‌شد.** تابع `normalizeMessage` زمان ارسال را در خروجی نمی‌گذاشت، پس هیچ‌کس نمی‌دانست پیام کِی آمده.

**ب) مرتب‌سازی روی شناسه بود.** شناسه‌ها UUID تصادفی‌اند:

```js
merged.sort((a, b) => String(b.id).localeCompare(String(a.id))); // الفبایی، نه زمانی
return b.id - a.id; // NaN
```

`"message-f9e8..." - "message-a1b2..."` مقدار `NaN` می‌دهد، یعنی ترتیب اصلاً عوض نمی‌شد. نتیجه واقعی با چهار پیام پشت سر هم: **چهارم، دوم، سوم، اول**.

**ج) خوانده‌نشده‌ها زور می‌زدند بالا بیایند.** پنل اول بر اساس خوانده‌نشده و بی‌پاسخ مرتب می‌کرد. یعنی به‌محض اینکه پیامی را می‌خواندید، زیر پیام‌های قدیمی‌تر می‌رفت.

حالا فقط زمان ارسال تعیین‌کننده است — در تب پیام‌ها، آیکون پیام و پروفایل کاربر، هر سه از یک تابع.

### ۷. پیام آزمایشی ساختگی

در هر بار لود پنل یک پیام «پشتیبان تستی» به صندوق اضافه می‌شد، پس شمارنده هیچ‌وقت با واقعیت نمی‌خواند و بج هرگز صفر نمی‌شد. حذف شد.

## هویت کاربر — چرا مهم است

پیام حالا `userId` ذخیره می‌کند، نه فقط نام و ایمیل:

```js
{ userId: "user-a1b2c3", email: "sam@test.com", source: "contact", ... }
```

بدون این، پاسخ ادمین جایی برای رفتن ندارد. تطبیق بر اساس **نام** برای دو کاربر هم‌نام اشتباه است.

- کاربر لاگین‌کرده → `userId` ثبت می‌شود
- کاربر مهمان از فرم تماس → فقط ایمیل (پاسخ از طریق ایمیل)
- پشتیبان هوشمند → **فقط برای کاربران لاگین‌کرده** (چون پاسخ باید به پروفایل برود)

---

## گزارش تخلف

گزینه «گزارش مشکل» از منوی موضوع درآمد و به بخش جداگانه‌ای زیر فرم ارسال پیام رفت با عنوان **گزارش تخلف**.

موضوع‌های باقی‌مانده: سوال آموزشی، نظر یا پیشنهاد، همکاری.

دکمه فعلاً `disabled` است با برچسب «به‌زودی». فرم پشتش در مرحله بعد ساخته می‌شود.

---

## اتصال آیکون هدر به تب

پاکت بالای صفحه و تب پیام‌ها یک صندوق‌اند:

- بج قرمز روی هر دو، از یک شمارنده (`isUnreadMessage`)
- دکمه «مشاهده همه پیام‌ها» ته پنل شناور → `switchView("messages")`
- خواندن یا پاسخ دادن، هر دو را همزمان به‌روز می‌کند

---

## پیام‌های من در پروفایل

تب جدید بین «سفارش‌های من» و «لیست علاقه‌مندی‌ها». هر گفتگو یک کارت با حباب‌های رنگی:

- حباب آبی (راست) = پیام کاربر
- حباب سبز (چپ) = پاسخ پشتیبانی
- برچسب «در انتظار پاسخ» یا «پاسخ داده شده»
- بج کنار نام تب = تعداد گفتگوهای پاسخ‌داده‌شده

---

## توابع

**سایت:**

```js
appApi.assistant.chat({ message, conversationId }); // پاسخ agent + شناسه گفتگو
appApi.support.sendMessage({ name, email, subject, message, source }); // ارجاع انسانی یا فرم تماس
appApi.support.myMessages(); // پیام‌های کاربر جاری
```

**پنل:**

```js
appApi.admin.messages.list();
appApi.admin.messages.reply(id, { text, adminName });
appApi.admin.messages.markRead(id);
```

**کمکی در `admin.js`:**

```js
isUnreadMessage(msg); // هر دو فیلد read و unread را می‌فهمد
isUnanswered(msg); // آخرین حباب از کاربر است؟
messageSourceBadge(msg); // برچسب منبع
```

## شکل پیام

```js
{
  id: "message-a1b2",
  userId: "user-x9",           // null برای مهمان
  sender: "سام به‌نام",
  email: "sam@test.com",
  subject: "question",
  source: "contact",           // یا "ai"
  text: "متن پیام",
  time: "۱۴۰۵/۰۵/۰۶",
  read: false,
  unread: true,                // همیشه برعکس read
  history: [
    { sender: "user",  name: "سام به‌نام", text: "...", time: "..." },
    { sender: "admin", name: "مدیر سایت",  text: "...", time: "..." }
  ]
}
```

**برای بک‌اند:** `history` منبع حقیقت است. `read` و `unread` باید همیشه برعکس هم باشند.

---

## آنچه هنوز مانده

- **فرم گزارش تخلف** — بخشش ساخته شد، دکمه غیرفعال است
- **پاسخ هوشمند واقعی** — بک‌اند باید `POST /assistant/chat` را به agent وصل کند، گفتگو را ذخیره کند و پاسخ `answer` و `conversationId` برگرداند.
- **اعلان به کاربر** — وقتی پاسخی می‌آید، کاربر تا وارد پروفایل نشود خبردار نمی‌شود
